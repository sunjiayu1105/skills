# 1 Skill 编写规范

本节适用于所有 Skill 的编写，也适用于在对话中拟定或修订 Skill 规则。

1. 拟稿与 Skill 的现有规则，或 Skill 中的规则彼此之间存在冲突、冗余或表述不一致时，先说明具体问题和拟采用的调整方式，待用户确认后再修改拟稿或规则。

## 1.1 修改边界

1. 用户明确保护的内容不得擅自修改。

2. 修改 Skill 文件前，在对话中说明变更范围，并展示拟写入的完整文本。用户确认后，按确认文本原样写入对应位置。

## 1.2 规则组织与表达

1. 规则按职责分类。有先后依赖时，按实际执行顺序排列。

2. 规则应适用于该 Skill 处理的同类任务。示例可采用具体场景。

3. 每条规则只说明一个主要要求。写清这条规则约束谁或什么内容、适用于哪些情况，以及执行时需要满足的条件。各条规则的职责应清楚，避免重叠。

4. 规则较长时，按含义拆成几条。拆分后应保留原有的条件和限制。

5. 示例应能说明对应的规则。规则有适用条件时，示例中的情形应符合这些条件。

6. 示例放在对应规则下方，与规则正文空一行，缩进与该条规则的正文对齐。示例以 `**示例**` 开头，标签后留一个半角空格，再写示例内容。

7. 相邻两条规则之间空一行。

## 1.3 Skill 标题和编号

1. `SKILL.md` 和 `references/` 下的每份 Markdown 文件各自独立编号。每份文件的第一个一级标题从 `1` 开始，子标题按 `1.1`、`1.1.1` 的层级编号，同级标题依次递增。

2. 新增、删除或调整标题后，核对标题层级、同级编号连续性及受影响的引用。

3. 每次拟定 Skill 变更时，检查 `SKILL.md` 和 `references/` 中的规则、示例和链接，找出受本次变更影响、需要同步更新或删除的内容。

4. 发现 Skill 变更需要同步更新或删除其他内容时，先在对话中列明受影响的位置和拟采取的处理方式，并展示拟写入的完整文本或拟删除的原文。经用户确认后，再按确认内容执行。

5. 引用 Skill 中的章节或规则时，链接文字写章节或规则名称。链接地址指向章节标题行或具体规则的起始行，由阅读器显示行号。

6. 被引用内容的位置变化后，更新链接地址中的行号。
