# 1 逐篇整理与复核

## 1.1 确定文档清单

1. 对清单中的全部文档逐篇执行本流程。未拆分或重组时，按用户指定的范围建立文档清单。

2. 拆分或重组后，以最终交付范围建立文档清单。清单应包含范围内保留、改名、顺延和新增的文档，以及汇总文档和导航文档。

   **示例** 用户指定 001–033，未拆分重组时，复核全部 33 篇。若拆分重组后为 001–038，则复核全部 38 篇。

3. 最终文档清单确定后，按清单建立本轮进度表。目录中已有《文档整理进度》时，用本轮记录替换上轮记录。首次执行时，按[确定四类配套文档的名称和排列顺序](/C:/Users/Administrator/.codex/skills/java-interview-doc-workflow/references/document-restructure.md:113)创建该文件。

4. 清单中的每篇文档对应一条记录，初始状态为「未开始」，整理次数为 `0`。

5. 同一次执行中，分批处理或暂停后继续时，更新本轮进度表中的对应记录，写明当前阶段，以及影响本篇继续编写、复核或完成的问题。

## 1.2 逐篇编写正文并复核

### 1.2.1 编写正文并复核

1. **编写正文。** 根据「问题」章节中的问题和考点，按[面试文档编写细则](/C:/Users/Administrator/.codex/skills/java-interview-doc-workflow/references/interview-document-writing.md:1)编写或修订正文。条目列有答题范围时，按其中限定的场景和深度展开。

2. **复核本轮文档。** 正文编写完成后，按《[单篇面试文档复核步骤](/C:/Users/Administrator/.codex/skills/java-interview-doc-workflow/references/review-checks.md:1)》复核本篇文档及受影响的关联内容。

### 1.2.2 判定继续或停止

1. 复核中发现有依据且能当轮修正的问题，就在当轮修正，并核对修改结果。AI 自检结束后，根据本轮结果判定本篇是已完成、继续下一轮，还是暂停。仅检查了标题、编号或链接时，按正文编写和全文复核的实际进度记录当前阶段。例如，正文已写完、尚待全文复核时，记为「正文已完成，待全文复核」。

   **示例**

   - **当轮完成。** 假设复核时发现，口述把迁移顺序写反了。项目已确认要先让旧表所有写入口启用双写，再固定历史扫描范围。当轮改正口述，核对详细方案中的顺序也正确，其余考点均已核完，AI 自检通过，即可判定「已完成」。

   - **继续下一轮。** 假设到了最后的 AI 自检，才发现详细方案虽然写对了，口述仍写着“先固定扫描范围，再启用双写”。此时能指出下一轮的具体工作：改正口述中的先后顺序，再核对口述与详细方案是否一致。现有项目材料足以支持这项修改，可以直接进入下一轮。

   - **暂停。** 假设本题问“项目为什么把启动锁的租约设为 15 分钟”，材料只给出了配置值。选值依据直接决定这道题能否答完整，应暂停并记录缺少的依据。如果本题问的是“租约提前到期后怎样防止重复派发”，且材料已能解释数据库如何判定派发资格，那么标明“15 分钟的取值依据待确认”，仍可完成本题。

2. 完整复核一轮后，如果同一问题仍然存在，且本轮未取得有效改进，暂停当前文档的整理，说明仍存在哪个问题以及暂停原因。

3. **完成本篇编写正文并复核。** 本篇要求的编写、检查和修改都已完成时，结束本篇编写正文并复核。仍有待确认或待验证事项的，写明事项及其对答案的影响。现有材料足以回答本题时，可以记录本篇完成。

4. **暂停本篇编写正文并复核。** 如果缺少的材料或用户尚未作出的决定导致本题无法答完整，结束当前文档的循环。取得所需材料或决定后，回到本篇完成编写正文并复核。

5. 如果仍有可在当前授权范围内、依据现有材料修正的问题，且未触发暂停条件，返回「[逐篇编写正文并复核](/C:/Users/Administrator/.codex/skills/java-interview-doc-workflow/references/per-document-revision-and-review.md:19)」开始下一轮。

6. 执行下一轮文档整理时，沿用本次已确认的考点和整理范围。

7. 判定为「暂停」或「已完成」时，结束本篇循环，再按[记录最终处理进度](/C:/Users/Administrator/.codex/skills/java-interview-doc-workflow/references/per-document-revision-and-review.md:49)同时更新当前文档和本次整理的进度表。

## 1.3 记录最终处理进度

1. 当前文档的循环结束后，将最终处理进度同时写入当前文档和本次整理的进度表中该篇文档的记录。

2. 最新记录按以下顺序写明：

   - 当前记录时间，格式为 `YYYY-MM-DD HH:mm`
   - 最终状态
   - 完成“逐篇编写正文并复核”的次数
   - 影响完成的问题
   - 本次整理结束的原因

3. 本篇已完成时，写明完成依据。本篇暂停时，写明导致暂停的具体问题。

4. 每篇文档和本次整理的进度表只保留最新一条最终处理进度记录，更新时覆盖上一条记录。

## 1.4 处理下一篇

1. 每完成一篇“逐篇编写正文并复核”，直接处理清单中下一篇可处理的文档。某篇需要用户确认时，先处理其余可处理的文档，待用户答复后再回到该篇。
                                                                                                                                                                                                                                                                 
2. 所有可处理的文档完成编写正文并复核后，本次整理的进度表应包含每篇文档的最终处理进度。对话中只提供该进度文档的链接和整体处理结论。
